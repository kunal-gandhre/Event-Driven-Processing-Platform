# Event-Driven Processing PlatformA Principal Engineer interview-quality reference implementation for a reliable, provider-agnostic event platform. It separates the business event contract from the transport, so changing `MESSAGING_PROVIDER` switches the implementation without changing domain code.## Design`POST /api/events` creates an immutable event. `EventPublisher` transports it through either Kafka or SNS/SQS. Consumers call a single idempotent `EventProcessor`; Flyway owns the deduplication table. This handles at-least-once delivery safely and makes retries/DLQs a transport concern.| Concern | Local/default | AWS ||---|---|---|| Event transport | Kafka | SNS topic + SQS queue || Object storage | MinIO | S3 || Database | PostgreSQL | RDS PostgreSQL || Deployment | Docker Compose / Kubernetes | Kubernetes + Terraform |## Run locallyPrerequisite: Docker Desktop and Maven 3.9+. Start dependencies with `docker compose up -d`, then run `mvn spring-boot:run`. Send an event:```bashcurl -X POST localhost:8080/api/events -H 'Content-Type: application/json' -d '{"eventType":"ORDER_CREATED","aggregateId":"order-42","payload":"{\\"customerId\\":\\"c-1\\"}"}'```MinIO is available at `http://localhost:9001` (`minioadmin` / `minioadmin`). The platform's object-store endpoint is configurable for an S3-compatible client: MinIO locally or S3 in AWS.Kafka UI is available at `http://localhost:8081`; use it to inspect the `processing.events` topic and consumer group.## Switch to AWS SNS/SQSProvision with `cd infra/terraform && terraform init && terraform apply`. Configure:```bashMESSAGING_PROVIDER=sqs AWS_REGION=eu-west-1 SNS_TOPIC_ARN=<terraform topic arn> SQS_QUEUE_URL=<terraform queue url> DATABASE_URL=<rds jdbc url> OBJECT_STORE_ENDPOINT=<s3 endpoint>```SNS publishes to the topic; the subscribed SQS queue is polled and acknowledged only after processing succeeds. The Terraform subscription uses raw message delivery so the consumer receives the event contract directly, and the queue has a five-attempt redrive policy to a DLQ.## Build, test, deployRun `mvn test` then `mvn package`. Build the image: `docker build -t event-driven-processing-platform:local .`. Deploy the app manifests with `kubectl apply -k k8s/base` after deploying dependency charts/manifests for PostgreSQL, Kafka and MinIO (or point configuration at managed AWS services).For a local Kubernetes cluster, load the image into the cluster runtime first (for example, `kind load docker-image event-driven-processing-platform:local` when using kind) and apply the base. Keep credentials in a secret manager rather than committing them for real environments.
